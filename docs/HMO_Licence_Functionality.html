Inspect360 HMO Licence Functionality

Complete product guide — upload, extract, assess, findings, cases and evidence.
Generated for Inspect360 · November 2026

Important disclaimer: HMO assessment in Inspect360 is a document and evidence status workflow. It is not a legal compliance certificate and does not prove lawful operation of an HMO.

1. Purpose

The HMO Compliance module helps property managers collect HMO licence documents, extract key fields, run rule-based checks against the property record, track gaps in evidence, and open remediation cases when critical issues appear.

Typical users: landlords, agents, compliance officers, and Inspect360 admins with HMO permissions.

2. Where it lives in the product

  • Sidebar: HMO Compliance (portfolio / cases dashboard)
  • Property page: HMO panel on a property (upload licence, review extraction, run assessment)
  • Module gate: Requires the HMO Compliance company module to be enabled for the organisation

3. End-to-end workflow

  1. Enable module — Organisation must have HMO Compliance turned on.
  2. Open a property — Go to the property and use the HMO panel.
  3. Upload & extract — Upload a PDF or image of the HMO licence. The system stores the file and extracts fields into a draft licence version.
  4. Review extracted fields — Check licence number, authority, dates, address, holder, etc. Re-upload if extraction looks wrong.
  5. Run assessment — Runs deterministic licence checks (LIC-01…LIC-05 and related stubs) against the extraction + property record.
  6. Review findings & status — Overall property HMO status and evidence completeness update.
  7. Case / tasks (when needed) — Critical expiry or missing schedules can open an HMO case with remediation tasks.
  8. Close the loop — Upload better evidence, re-assess, complete tasks, and close cases when verified.

4. Upload & extract

4.1 Accepted files

PDF, JPG/JPEG, PNG, WebP, HEIC/HEIF, GIF, BMP (and plain text for fixtures). Max size typically 25 MB.

4.2 What extraction produces

A structured licence extraction object, including:

FieldMeaning
Property addressAddress printed on the licence
Licence numberCouncil licence reference
Issuing authorityCouncil / borough that issued the licence
Issue date / expiry dateValidity window of the uploaded document
Maximum individualsMax occupancy stated on the licence (when found)
Holder / managerNamed licence holder or manager
ConditionsExtracted licence conditions (when available)
Missing attachmentsSchedules/annexes referenced but not present in the upload
ConfidencePer-field confidence (e.g. Low confidence when OCR fails)

4.3 How extraction works

  • PDF text: Text layer parsed from the PDF when available.
  • Images / scans: Vision / OCR when AI keys are configured.
  • Heuristic + AI parsers: Map free text into structured fields; content is treated as untrusted data.
  • Versioning: Each upload creates a licence version (draft → current after confirmation/assessment flow).
If licence number shows “Not found” or Low confidence, assessment will flag gaps. Prefer a clear multi-page licence PDF (including schedules) before relying on results.

5. Run assessment — detailed behaviour

Run assessment does not re-read the PDF. It evaluates the already-extracted fields against the property record using fixed rules, then saves:

  • An assessment record
  • Individual findings (one per check)
  • Updated overall status and evidence completeness %
  • Optionally an HMO case + tasks
  • An audit event (assessment.run)

5.1 Licence checks (LIC)

CheckWhat it evaluatesTypical outcomes
LIC-01 Address on licence vs property address Match → compliant; postcode-only match → human review; mismatch → critical review (no auto-link)
LIC-02 Licence number + issuing authority present Missing → evidence missing; present → still needs human authenticity review (upload ≠ council verification)
LIC-03 Expiry date vs today Future expiry → document valid window OK; expired → critical review (does not assert unlawful operation); missing date → evidence missing
LIC-04 Licence holder vs landlord/contact on file Missing holder → evidence missing; mismatch → potential risk / review
LIC-05 Referenced schedules/annexes missing from upload Missing attachments → evidence missing (high); none flagged → compliant for this check

5.2 Broader check stubs (not fully assessed yet)

Additional checks are reserved and currently return EVIDENCE_MISSING until occupancy/room/amenity/safety data is supplied:

OCC-01…03 (occupancy), ROOM-01/02 (room sizes/use), AMEN-01 (amenities), SAF-01 (safety certificates), COND-01 (conditions/hazards), LOC-01 (local standards), PLAN-01 (planning), MGMT-01 (display/notices).

Evidence completeness % summarises how much of the expected evidence set is present across findings.

6. Automatic case opening

After assessment, Inspect360 may open an HMO remediation case when:

  • LIC-03 is CRITICAL and not verified compliant (e.g. expired uploaded licence), or
  • LIC-05 is EVIDENCE_MISSING (missing schedules/annexes)

If an open case already exists for the property, a duplicate is not created. New cases can be seeded with remediation tasks (e.g. obtain current licensing position, upload full schedules).

6.1 Case lifecycle

OPEN → TRIAGED → IN_PROGRESS → AWAITING_EVIDENCE / AWAITING_REVIEW → READY_FOR_SIGNOFF → VERIFIED_CLOSED (also REOPENED / CANCELLED_AS_DUPLICATE).

6.2 Task lifecycle

OPEN → ASSIGNED → IN_PROGRESS → EVIDENCE_REQUESTED → EVIDENCE_RECEIVED → AWAITING_VERIFICATION → VERIFIED_CLOSED (also REOPENED / CANCELLED).

8. Permissions

Access is gated by role permissions, including:

  • hmo.licence.upload / hmo.licence.confirm
  • hmo.assessment.run
  • hmo.case.read / hmo.case.write / hmo.case.assign
  • hmo.critical.close, hmo.occupancy.read, hmo.notification.send, hmo.rule.approve

9. Related capabilities (beyond the licence button)

  • Occupancy checks — Compare household/occupancy against licence maxima (OCC checks).
  • Room baselines — England sleeping-room floor-area baselines (Housing Act 2004 Sch.4) for ROOM checks when room data exists.
  • Dashboard / metrics — Portfolio views of statuses, open cases, evidence gaps.
  • Bulk import — Idempotent licence import by content hash for large portfolios.
  • Audit trail — Assessment runs and key actions are audited.
  • Integrations — Adapters (e.g. Reapit) can feed property context where configured.

10. Practical operator guide

  1. Upload the full licence pack (main grant + schedules/annexes).
  2. Confirm extracted fields before assessing — especially address, number, expiry.
  3. Click Run assessment.
  4. If status is Action/Critical/Review, open the case and complete evidence tasks.
  5. Re-upload corrected documents and re-run assessment after fixes.
  6. Treat “Verified compliant” as document/evidence status for assessed checks, not legal advice.
