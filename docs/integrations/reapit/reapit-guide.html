How Reapit is integrated

Each Inspect360 organisation can connect its own Reapit agency account. After connect, Inspect360 stores the Reapit customer id and encrypted tokens on the server (never in the browser). A background worker then imports data and keeps it updated.

1

Connect (OAuth) Owner clicks Connect in Settings à Integrations. Reapit authorises the app. Inspect360 saves the customer id and encrypted tokens, then queues an initial sync.

2

Full sync (job worker) Jobs run in Postgres (no Redis). Order: lettings properties → landlords/contacts → tenancies. Each Reapit id is mapped to an Inspect360 row so re-sync is idempotent.

3

Ongoing updates (webhooks) Reapit posts to /api/webhooks/reapit. Signatures are verified (Ed25519). Events are de-duplicated by eventId. The organisation is resolved from Reapit’s customer id — not from a client-supplied org header.

4

Ownership split Reapit overwrites identity fields on mapped rows (name, address, landlord, tenant, lease dates, rent). Inspect360 keeps owning inspections, maintenance, compliance, assets, and disputes — those are never written back to Reapit in v1.

How it helps us

Less double entry

Properties, tenants, landlords, and tenancy dates flow from Reapit instead of being typed twice.

Ready for operations

Once synced, the portfolio is ready for inspections, maintenance, compliance, and rent tools inside Inspect360.

Stays up to date

Initial/manual sync plus webhooks keep changes from Reapit flowing in without daily CSV imports.

Safe boundaries

Tokens stay server-side. Org isolation is enforced. Disconnecting drops tokens but keeps Inspect360 history.

What needs to be done to use it

These steps are done once per environment (dev / production), then each agency owner connects their own Reapit account.

1. Reapit Developer Portal (external)

  • Register an Inspect360 app in the Reapit Developer Portal.
  • Redirect URL: {BASE_URL}/api/reapit/oauth/callback
  • Webhook URL: {BASE_URL}/api/webhooks/reapit
  • Scopes: properties.read, contacts.read, landlords.read, tenancies.read, and tenancies.write (required by Reapit for tenancy webhook delivery — Inspect360 still does not write to Reapit).
  • Have a sandbox / customer id available for testing (e.g. SBOX).

How to use it day to day

  1. Owner opens Settings → Integrations.
  2. In the Reapit card, click Connect Reapit and complete Reapit login / consent.
  3. After redirect, an initial sync is queued automatically. Status, entity counts, and sync history appear on the same card.
  4. Use Sync now anytime for a full refresh (owner only).
  5. On a property detail page (owner/clerk), mapped properties show Source: Reapit and last synced time.
  6. Landlords appear under Contacts with type Landlord. Tenants appear as tenant users/assignments (portal off until you enable access).
  7. Disconnect disables the link and drops tokens; Inspect360 property/tenant data remains.

Connect / disconnect / sync are owner actions. Clerks can view connection status and sync history. Trial / credit locks also apply to /api/reapit endpoints (except the public webhook path).
