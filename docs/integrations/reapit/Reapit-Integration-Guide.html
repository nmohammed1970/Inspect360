2. What this integration does

The Reapit integration is a one-way bridge from Reapit Foundations (your agency CRM / property management system) into Inspect360 (inspections, compliance, maintenance, and tenant portal).

Simple idea: keep property, landlord, tenant, and tenancy master data in Reapit. Inspect360 pulls that data in so you can run inspections and compliance without re-typing addresses, tenants, or lease dates.

Inspect360 does not write inspections, maintenance jobs, or compliance documents back into Reapit in version 1.

3. How it is built into Inspect360

3.1 High-level flow

Owner (Settings → Integrations) → Connect with Reapit OAuth → Inspect360 stores encrypted tokens + Reapit customer id → Background worker syncs properties → landlords/contacts → tenancies → Ongoing: Reapit webhooks trigger updates for changed records

3.2 Main building blocks

PieceRole in Inspect360
Settings → Integrations Owner connects, syncs, disconnects; clerks can view status.
reapit_connections One connection per organisation; encrypted tokens; Reapit customer id.
reapit_entity_mappings Links each Reapit id to the matching Inspect360 property, contact, or tenancy.
Job worker (Postgres) Runs initial/manual sync and webhook updates without Redis.
POST /api/webhooks/reapit Receives Reapit events, verifies Ed25519 signature, queues safe upserts.

3.3 Who owns what

Reapit owns Property name & address, landlord contact, tenant identity, lease dates, rent & deposit figures (on mapped rows only).
Inspect360 owns Inspections, maintenance, compliance documents, assets, disputes, comparison reports, and all portal/workflow features.

4. What data comes across

From ReapitInto Inspect360Notes
Lettings properties properties Sales-only stock is skipped. Address is formatted into one address field.
Landlords Contacts with type Landlord Not a login user. Optional link on the property via landlord contact.
Contacts / tenants Contacts + tenant users Portal access starts off. No invite email unless you enable portal later.
Tenancies tenant_assignments Lease dates, rent, deposit. Ended tenancies become inactive (not deleted).
Important: Inspect360 never hard-deletes properties or users just because Reapit archived them. Mapped identity fields can be updated from Reapit; your inspection/compliance history stays intact.

5. What needs to be done to use it

There are two layers: platform setup (once, by your technical team) and agency connect (per organisation, by an owner).

5.1 Platform / server checklist

  1. Register an app in the Reapit Developer Portal (sandbox customer such as SBOX for testing).
  2. Set redirect URL to {BASE_URL}/api/reapit/oauth/callback.
  3. Set webhook URL to {BASE_URL}/api/webhooks/reapit.
  4. Request scopes: properties.read, contacts.read, landlords.read, tenancies.read, and tenancies.write (needed for tenancy webhook delivery even though Inspect360 does not write to Reapit).
  5. Add environment variables on the server (see table below).
  6. Run the Contabo SQL migration addReapitIntegration.sql as database user creativecloud, then grant access to inspect360.
  7. Deploy / restart the app so the Reapit worker is running (ENABLE_REAPIT_WORKER defaults to on).

5.2 Environment variables

VariablePurpose
REAPIT_CLIENT_IDApp client id from Reapit
REAPIT_CLIENT_SECRETApp client secret
REAPIT_CONNECT_URLUsually https://connect.reapit.cloud
REAPIT_API_URLUsually https://platform.reapit.cloud
REAPIT_REDIRECT_URIOptional override of OAuth callback
INTEGRATION_ENCRYPTION_KEY32-byte hex secret for token encryption (e.g. openssl rand -hex 32)
ENABLE_REAPIT_WORKERSet false only to pause background sync

5.3 Agency owner checklist

  1. Sign in to Inspect360 as an owner.
  2. Open Settings → Integrations.
  3. Click Connect Reapit and complete Reapit login / consent.
  4. Wait for the initial sync (status and entity counts appear on the same card).
  5. Use Sync now later for a full refresh; day-to-day changes can also arrive via webhooks.
  6. On a property detail page (owner/clerk), look for Source: Reapit when the property came from sync.

6. How to use it day to day

  • Connect Once per organisation. Tokens never appear in the browser.
  • Sync Initial sync loads lettings properties, landlords, contacts, and tenancies. Manual sync re-queues a full run.
  • Work Schedule inspections, upload compliance, raise maintenance — as usual — against the imported properties and tenants.
  • Landlords Appear under Contacts as type Landlord (address book only; no portal login).
  • Tenants Exist as tenant users with portal off until you deliberately enable access.
  • Disconnect Stops sync and drops tokens. Existing Inspect360 properties, tenants, and history remain.
Clerks can view connection status and sync history. Only owners can connect, disconnect, or start a sync.

7. How it helps us

BenefitWhy it matters
No double data entry Properties, tenants, and lease dates flow from Reapit instead of being typed twice.
Faster onboarding A new agency can connect once and populate Inspect360 from their live CRM stock.
Cleaner source of truth Reapit remains the commercial/lettings system; Inspect360 focuses on inspections and compliance quality.
Safer updates Only mapped rows are updated. Manually created Inspect360 properties are left alone.
Live maintenance Webhooks keep records fresher when properties, contacts, landlords, or tenancies change in Reapit.
Rent awareness Tenancy rent/deposit fields sync and feed Inspect360’s existing rent-period generation.

8. Security and v1 limits

Security highlights

  • OAuth state is signed and tied to the organisation (CSRF protection).
  • Tokens are encrypted at rest with AES-256-GCM.
  • Webhooks verify Reapit Ed25519 signatures; organisation is resolved from Reapit customer id, not a client-supplied org header.
  • Connector APIs respect trial/credit entitlement locks; the webhook endpoint remains reachable for Reapit delivery.

Not in version 1

  • Writing inspections or maintenance back to Reapit
  • Bulk import of Reapit document binaries / property image blitz
  • Auto-creating blocks from Reapit building structures
  • Importing sales-only property stock
