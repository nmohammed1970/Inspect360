End-to-end process flow, implementation controls and four user interface screens

Version 2.0  ·  20 November 2026  ·  Developer handover

Purpose

Enable a tenant or inspector to report a maintenance issue once, and allow Inspect360 to manage the complete lifecycle: Admin triage, team or direct allocation, quotation approval, confirmed visit, repair evidence, completion sign-off, external contractor invoice and the permanent property maintenance record.

Handover package

  • This Word document: operational workflow, decisions, responsibilities and screen designs.
  • Cursor Pro Markdown specification: state machine, data model, permissions, API actions, validation, audit and acceptance tests.
  • Interactive HTML screen prototype: quotation, invoice, end-of-job checklist/photos and completed work-order record.
  • Four PNG screen references for rapid implementation and review.

Visual identity — match existing Inspect360 HMO screen

  • White 230px sidebar with inspect360 logo; pale mint active navigation; same WORKSPACE / MANAGEMENT groups and icons.
  • White breadcrumb/header bar; pale grey-blue page canvas; deep navy headings, muted blue-grey labels, teal primary buttons.
  • Thin bordered white cards, four-column summary tiles, compact status tags and warm amber next-action panels.
  • Quotation, invoice, completion and permanent work order pages follow the same hierarchy and card spacing as the HMO overview.
  • Build inside the existing Inspect360 app shell. Use the supplied HTML and PNGs as visual references only; do not deploy demo banners or local fake actions.

The floating chat overlay visible at the bottom of the reference screenshot is not part of Inspect360 and must not be reproduced.

Four screens to implement

Quotation: scope, line items, subtotal/tax, approval route and linked work order. Invoice: document and item comparison, payment state. End-of-job: engineer checklist, before/after evidence and review. Permanent work-order record: linked property, full activity, evidence, quote and invoice.

Responsive, accessible and secure

Compare screens at 1564×960 desktop and 390×844 mobile. UI-only mock controls are not substitutes for server-side approval, photo uploads, role validation, monetary calculation or operational audit. Screenshot-derived colours are approximate; use existing app tokens in production.

Architecture decisions — do not compromise

Decision

Required behaviour

Single source of truth

Link to existing Inspect360 property, unit, room/asset, tenant and inspection entities. No duplicate silos.

Atomic team assignment

The first eligible committed acceptance wins. Late acceptances cannot overwrite an existing assignment.

Authority before work

Approval checks occur server-side. Pre-approval is a configurable policy, not an engineer switch.

Separate operational and invoice statuses

A completed/closed repair can still have an outstanding invoice; approval is not payment.

Evidence and audit

Every major decision, photo, checklist, quote version and cost remains traceable against the property.

01 / End-to-end process flow

The main path is vertical. Amber branches represent exceptions that return to an earlier stage. Invoices apply only to external contractors; internal labour and materials are recorded as costs.

02 / Operational process — intake to authorisation

Step / owner

Action and user experience

Automated Inspect360 requirements

1. Tenant / Inspector

Report issue via app or web; select property, room/asset, describe defect, upload images/video. Inspection-origin issue inherits point and evidence.

Assign reference; create request; link property and original inspection; acknowledge reporter; notify Maintenance Admin group.

2. Maintenance Admin

Open queue; review photos, history and duplicate risks; determine priority; accept, request more information, link duplicate or reject with reason.

Record triage event; enforce scope; track configured priority deadlines; display suggested AI category only as advice.

3. Admin / Engineer

Select individual from schedule or team broadcast. Engineer Accept/Decline; first eligible acceptance gets job.

Validate skills/credentials, roster and calendar; atomic acceptance; expire other offers; escalate unclaimed jobs.

4. Reallocation

If engineer cancels, record reason; prompt next eligible candidate or rebroadcast; if none found, escalate Admin.

Archive previous allocation; revoke previous appointment if impacted; notify tenant and team; maintain history.

5. Engineer / Approver

Check pre-approved policy. If not covered, inspect if needed, itemise labour/parts and submit quote. Manager approves/rejects/requests revision.

Threshold rules and no self-approval; preserve quote versions; block unapproved work and out-of-scope variation.

Quote / permission nuance

A site assessment can be scheduled before quotation approval. However the actual remedial work must not proceed beyond authorised scope until the necessary approval is recorded. A suitably documented emergency exception is managed by a separate policy.

03 / Operational process — visit to closure

Step / owner

Action and user experience

Automated Inspect360 requirements

6. Scheduling

Admin or engineer selects an available slot. Tenant confirms or requests a change.

Once confirmed, send tenant engineer name, authorised photograph/avatar, company and arrival window by app/email.

7. Engineer visit

Engineer opens job in app; logs arrival; takes before photos; carries out work; logs time, materials and outcomes; takes after photos and completes checklist.

Save drafts/offline uploads where supported; enforce evidence and approvals; allow unable-to-complete/follow-up reason.

8. Admin sign-off

Admin checks repair notes, evidence and checklist; accepts or sends back for rectification.

Record identity/time/reason; notify reporter when accepted; retain rejected completion and revisions.

9. Invoice & finance

External contractor submits invoice from accepted work. Admin matches it against approved quote and work, queries or approves; finance tracks status.

Separate invoice and payment statuses; flag duplicates and variance; internal engineer only logs labour/materials.

10. Property history

Close operations after sign-off, preserve linked records and allow authorised reopening for failed repairs.

One permanent work-order record shows original issue, dispatch, approvals, visits, evidence, costs, payments and audit.

Critical alerts

  • Notify Maintenance Admin on every new request, unclaimed allocation, stalled approval, deadline breach and submitted completion.
  • Notify tenant of request acknowledgement, confirmed visit, reschedule/cancellation, accepted completion and reopening.
  • Notify engineer on offer, assignment, approval/variation decision, confirmed appointment and request for rectification.
  • Notify finance/admin of external invoices, variance, payment approval or long-outstanding invoice.

04 / Role boundaries, settings & exceptions

User / group

Key access

Tenant

Report and track own maintenance; add information; confirm appointments; report unresolved work. No internal finance, approvals or private Admin notes.

Inspector

Create maintenance from inspection point and pass existing context/photos; no spending approval.

Maintenance Admin

Triage, assign, broadcast, review quote within authority, schedule, inspect evidence, approve completion, manage invoice workflow.

Engineer / external contractor

Accept job offer, prepare quote, confirm availability, upload work evidence, invoice if external. May not approve own quote/invoice.

Finance / authorised approver

Approve thresholds or payments within policy; keep a separate immutable approval trail.

Eco Admin

Configure teams, distribution groups, templates, emergency procedures, priorities, rules, escalations and permissions.

Settings the developer must expose

  • Maintenance Admin distribution group and team/engineer membership, qualifications, availability and reassignment order.
  • Priority response targets and escalation/reminder intervals; separate emergency routing.
  • Pre-approval categories and spend limits; approvers and escalation thresholds.
  • Checklists by trade or issue type, required photos, variation policy and tenant access rules.
  • Invoice approval roles, currency/tax settings, payment-status controls and notification channels.

Exceptions to handle explicitly

Unclaimed work; simultaneous acceptance; non-qualified engineer; no tenant access; cancelled appointment; rejected or revised quote; scope/price variation; offline media upload; failed repair; rejected completion; invoice discrepancy; duplicate request; revoked user permissions. Every exception needs status, named owner, next action and audit event.

SCREEN DESIGN

05 / Quotation builder

Engineer prepares an itemised repair quote linked to the work order. A named Admin or authorised approver decides whether the quote can be acted upon.

Figure — Inspect360 implementation mockup with illustrative data; not a connected production screen.

Developer implementation notes

  • Line items and currency/tax are configurable; totals must be recalculated on the server.
  • Approved quote versions are immutable; changes must create a revision or linked variation.
  • Pre-approved jobs bypass quote only when a stored organisation/property policy authorises them.

SCREEN DESIGN

06 / External contractor invoice

After completion is accepted, the external engineer invoices against the authorised work and approved quotation.

Figure — Inspect360 implementation mockup with illustrative data; not a connected production screen.

Developer implementation notes

  • Show approved quote, accepted work value, invoice total and any discrepancy.
  • Invoice approval does not equal payment; payment status is an independent audited action.
  • Internal employees record hours/materials instead of producing external payable invoices.

SCREEN DESIGN

07 / End-of-job checklist & photos

Engineer PWA view combines visit details, trade-specific checklist, before-and-after photographic evidence and completion submission.

Figure — Inspect360 implementation mockup with illustrative data; not a connected production screen.

Developer implementation notes

  • Require mandated answers and before/after images before submitting for Admin review.
  • Support drafts, queued uploads and clear retry indicators. Provide unable-to-complete path.
  • Completion submission is not final acceptance; Admin must verify and approve the repair.

SCREEN DESIGN

08 / Final work order record

A permanent property-linked record displays the original issue, the complete audit trail, approved cost, repair evidence, invoices and connected property/inspection references.

Figure — Inspect360 implementation mockup with illustrative data; not a connected production screen.

Developer implementation notes

  • Use one canonical work-order ID and preserve revisions, reassignments and reopened work.
  • Enforce role-based disclosure: tenants must not see internal financial breakdowns or staff notes.
  • Maintain links to inventory, inspection, compliance and future check-out comparison records.

09 / Minimum release acceptance criteria

Area

Test expected to pass

Tenant & inspector

Issue created once; correct property and photos attached; acknowledgement sent; tenant isolation enforced.

Admin intake

Group configured in Settings receives notification; issue can be prioritised, rejected/merged or sent back for more details.

Distribution

Direct assignment works; team offer selects first eligible committed acceptance exactly once even under concurrency.

Cancellation

Engineer cancellation returns job to a defined next allocation step and updates affected tenant appointment.

Quote policy

Authorisation enforced server-side; no self-approval; above-limit approval correctly escalated; versions preserved.

Scheduling

Tenant sees engineer identity/photo and arrival time only after appropriate confirmation.

Completion

Required checklist/photos enforced; Admin can accept or return for rectification; evidence remains linked.

Invoice

Only external contractor can submit payable invoice; quote variance flagged; approval separate from payment.

Record & audit

Property view includes full chronological chain; reopening links to original without overwriting history.

Security & regression

Organisation/role checks, secure media, idempotent events, reminders, mobile and existing app integrations pass.
