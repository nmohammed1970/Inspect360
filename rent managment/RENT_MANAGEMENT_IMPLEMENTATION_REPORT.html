Rent Management — Implementation Report

Inspect360 · Product / engineering handover
Date: 25 November 2026 · Spec: Inspect360_Rent_Management_Developer_Specification.md v1.0
Scope: Phase 1

Summary. Rent Management is a portfolio operational subledger built on existing tenancies (tenant_assignments). It does not create a second tenancy database or a full accounting product. Money is stored in integer minor units (pence). Payments require a confirmed receipt — there is no silent “Mark Paid” toggle. The module is gated by the existing organisation flag rentals (requires Tenancies).

1. What was built

1.1 Database

  • Migration: server/migrations/addRentManagement.sql (+ runner server/migrations/addRentManagement.ts)
  • Schema: shared/rentSchema.ts
  • Core tables: rent_accounts, rent_schedule_versions, rent_charges, rent_receipts, rent_allocations, rent_adjustments
  • Ops tables: bank transactions / reconciliation, arrears cases & events, payment plans, rent reviews, statement snapshots, financial audit events
  • One rent_accounts row per tenancy (unique). Deposits stay on property_deposits and are never auto-allocated to rent.

2. How it works day-to-day

2.1 Enable & migrate

  1. Apply addRentManagement.sql on Contabo as creativecloud against inspect360_dev / inspect360 (GRANTs included for app user).
  2. Settings → Internal Modules → ensure Tenancies and Rentals are ON.
  3. Optional: Rent management → Settings → Provision accounts and/or Legacy migration (dry-run first).
  4. Demo seed (local/dev): npx tsx server/scripts/seedRentTestData.ts (targets washi51214@gmail.com org).

2.2 Tenancy → rent account

Create/update a tenancy with monthly rent + due day
→ System provisions rent_accounts + approved monthly schedule version
→ Charge engine generates future periods (idempotent)
→ Daily/hourly job posts due charges and refreshes overdue / paid statuses

2.3 Recording a payment

Operator: Record receipt (portfolio page or property Rent tab)
→ Confirmed receipt created with idempotency key support
→ Default allocation: oldest unpaid charge first (partial/split allowed)
→ Excess amount becomes unapplied credit on the account — never treated as deposit
→ Charge statuses update: due → part paid → paid / overdue as appropriate

2.4 Arrears

Job detects unpaid charges with due date before as-of
→ Opens/updates one arrears case per tenancy
→ Operator records notes, hold/dispute, plan, or manual escalation
→ When balance clears, case resolves automatically with history kept
No automated eviction, possession, guarantor demand, or late fees

2.5 Bank CSV reconciliation (MVP)

  1. Paste CSV with header: date,amount,reference,counterparty,sourceId
  2. Import dedupes by fingerprint / source ID
  3. Suggested matches appear when payer reference aligns
  4. Confirm match → creates confirmed receipt and allocates

2.6 Rent reviews (basic)

  • England PRS rules: generally no increase in first 12 months; at most once per year; ≥2 months’ notice
  • Assessment can mark manual review; activation refused if eligibility fails
  • Notices are never auto-served; live schedule unchanged until lawful effective date + approval

2.7 Statements

  • Generate for a tenancy account and date range → stored snapshot + audit
  • Download CSV from statement history

4. Key business rules

RuleBehaviour
MoneyInteger minor units only — no floating-point ledger math
Joint tenancyOne liability / one ledger per tenancy assignment
No silent PaidLegacy rent-period “Mark Collected” returns 400; use a receipt
DepositsSeparate table; never auto-allocate to rent
Excess cashUnapplied credit or suspense — not silent rent/deposit
RolesOwner/clerk operate rent APIs; inspectors/maintenance have no rent access by default
Module OFF/api/rent/* gated by rentals; nav hidden
AuditReceipts, allocations, cases, reviews, statements, migration writes financial audit events

6. Explicitly out of scope (Phase 2)

  • Hosted payment providers / Direct Debit / open banking feeds
  • Full client-money reconciliation sign-off and owner payouts
  • Accounting exports (e.g. Xero), AI bank-match suggestions
  • Late interest/fees (disabled by default until legal validation)
