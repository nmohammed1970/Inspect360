Communications Hub — Implementation Report

Inspect360 · Product / engineering handover
Date: 25 November 2026 · Spec reference: COMMUNICATIONS_HUB_SPEC.md v1.0

Summary. Communications Hub is a new first-class case domain that wraps (does not replace) maintenance, tenant portal, and portfolio records. It is gated by an organisation module flag that defaults OFF. Staff get an operational inbox and case workspace; tenants get unified requests with public statuses only.

1. What we added

1.1 Database & module

  • Migration: server/migrations/addCommunicationsHub.sql
  • Org columns: communications_enabled (default false), emergency guidance, default-landing flag
  • Tables: categories, cases, messages, actions, approvals, case links, audit events, SLA events, channel events, document sequences (COM-YYYY-#####)
  • Company module key communications (opt-in, like HMO)

1.2 Backend (server/communications/)

AreaWhat it does
Case serviceCreate / list / patch (optimistic version), assign, messages, notes, actions, approvals, resolve/reopen, cancel/duplicate, escalate
Maintenance bridgeOn maintenance create, idempotently create/link one Maintenance-category case
Audit & SLAAppend-only audit; first-response / resolution timers; audited pause/resume
ChannelsEmail/WhatsApp/stub adapters, signed webhooks, delivery status, identity review & dead-letter queues
AI (Ivy-assisted)Suggestion only (category, priority, draft, risk flags); safety keywords independent of model; never auto-apply / auto-send
AnalyticsVolume, SLA %, median response/resolution, reopen rate, category/owner breakdown, attention list, logged export

1.3 Staff UI

  • Inbox — /communications (queues | list | preview)
  • Case workspace — conversation, internal notes, actions, approvals, links, audit, channel log, AI panel
  • Analytics — /communications/analytics
  • Workflow settings — /communications/settings
  • Sidebar group: Inbox, My work, Approvals, Analytics, Settings (permission-gated)
  • Activity tabs on Property and Tenant detail; tenancy-scoped activity under tenancy history
  • Linked cases panel on maintenance request, work order, and inspection records

1.4 Tenant UI

  • Unified My requests when Communications is ON
  • New request with shortcuts (repair → maintenance bridge; rent/tenancy/general → case only)
  • Request detail: tenant-visible thread only; reply + “Issue still persists”
  • Public statuses only: Received, Under review, In progress, Waiting for you, Resolved, Closed

2. How it works day-to-day

2.1 Enable for an organisation

  1. Apply SQL migration on Contabo as creativecloud (dev/prod DB), grants already in the migration for app user inspect360.
  2. Settings → Internal Modules → turn on Communications → Save.
  3. Default categories are seeded (Maintenance, Rent & payments, Tenancy, … Internal).

2.2 Tenant submits a request

Tenant → New request → chooses shortcut + subject/details
→ API creates a case with reference COM-YYYY-#####
→ If shortcut is repair/maintenance: also creates a maintenance request and links the case once (no duplicate WO/case on retry)
→ Tenant sees public status only; confirmation uses the case reference

2.3 Operator works a case

Inbox queues (All / My cases / Unassigned / Urgent / Overdue / Approvals / Awaiting tenant / Closed)
→ Open workspace
→ Assign · Reply (tenant-visible) · Internal note (never to tenant) · Tasks · Request approval
→ Optional: log phone/email/WhatsApp · escalate · link records · apply AI suggestion manually
→ Resolve only with resolution summary; blocked if required tasks open or required approval missing
→ Reopen keeps prior closure data and records a new reason

2.4 Maintenance relationship (non-negotiable)

  • Communications does not replace Fixflo / maintenance chat / WO process.
  • Existing maintenance create paths auto-bridge to a case when the module is ON.
  • At most one work order may be created-from-case (409 on second).
  • Case workspace deep-links into the linked maintenance discussion.

2.5 Visibility & security rules

RuleBehaviour
Module OFFAll /api/communications/* routes return 403; nav hidden
Org scopeEvery read/write is organisation-scoped
Optimistic lockingPATCH / resolve / assign require current version (409 on stale)
Internal notesStored as visibility=internal; tenant APIs never return them
Reply ≠ resolveMessages do not close a case; resolve is a deliberate action
Closed replyTenant message on closed case alerts owner to review/reopen
NotificationsAssignment, tenant reply, approval, overdue — no sensitive subjects

3. Lifecycle & categories

Statuses: new → triaged → assigned → in progress → resolved → closed; waiting: awaiting_tenant · awaiting_approval · awaiting_third_party; terminal extras: cancelled · duplicate (require reason; duplicate links canonical case).

Seeded categories: Maintenance; Rent & payments; Tenancy; Complaints; Health & safety; Access; Property alterations; Documentation; Inspections; Move-in; Move-out; General; Internal.

Workflow settings store routing defaults, SLA hours, approval policy, and notify/escalate toggles. Each new case snapshots the policy version used at creation.

4. Channels, AI, analytics (later phases included)

Phase 2 Webhooks under /api/communications/webhooks/:provider with signature check and idempotent event IDs; identity review for unmatched senders; dead-letter UI in settings.

Phase 3 AI triage panel on the case workspace — human accept/edit only; safety keyword fallback (e.g. gas leak) even if the model is down.

Phase 4–5 Configurable SLAs / escalations; analytics dashboard with documented denominators; optional org setting to land staff on the Communications inbox.

7. Operator checklist after deploy

  1. Run migration on Contabo (creativecloud).
  2. Enable Communications for a pilot org.
  3. Confirm categories appear under Workflow settings.
  4. Tenant: submit repair + general request; verify references and public statuses.
  5. Staff: assign, internal note, resolve; confirm tenant cannot see the note.
  6. Create maintenance request twice / retry bridge — still one linked case.
  7. Optional: set emergency guidance and default landing in Communications settings.
