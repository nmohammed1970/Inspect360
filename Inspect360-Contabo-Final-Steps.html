Compose is already on the server. Do these on your PC first, then Contabo.

1 Build image Your PC — PowerShell

cd "d:\Work-Projects\New Server\Inspect360NewServer"
docker build -t inspect360:local .

Wait until you see Successfully tagged inspect360:local. First build can take 10–30 minutes.

2 Save image to a file Your PC

docker save inspect360:local -o inspect360-local.tar

Creates a large .tar file in the project folder.

3 Upload tar to Contabo Your PC

scp inspect360-local.tar root@169.58.40.94:/tmp/

4 Load image on server Contabo SSH

docker load -i /tmp/inspect360-local.tar
docker images | grep inspect360

5 Start the container Contabo

cd /opt/inspect360
IMAGE=inspect360:local docker compose -f docker-compose.contabo.yml up -d

docker ps --format "table {{.Names}}\t{{.Status}}\t{{.Ports}}"
docker logs --tail 100 inspect360
docker inspect inspect360 --format '{{range $k,$v := .NetworkSettings.Networks}}{{$k}}{{"\n"}}{{end}}'

Expect:

  • Container named inspect360 is Up
  • Network shows caddy
  • Logs show server start (no DB connection errors)
If DB fails: confirm DATABASE_URL host is postgres, and both inspect360 + postgres are on network caddy.

After container is Up Caddy route

Caddy is already a Docker container. Add a site block so the domain reaches Inspect360.

6 Find Caddyfile location Contabo

docker inspect caddy --format '{{range .Mounts}}{{.Source}} -> {{.Destination}}{{"\n"}}{{end}}'

Edit the Source path on the host (that’s the real file).

7 Backup + add site block Contabo

# Example — use YOUR Source path from step 6
cp /path/to/Caddyfile /path/to/Caddyfile.bak.$(date +%F)
nano /path/to/Caddyfile

Add this block (keep existing HeyTeam / other blocks):

portal.inspect360.ai {
    encode gzip
    reverse_proxy inspect360:5000
}
Why this works Caddy and Inspect360 share Docker network caddy, so Caddy can resolve hostname inspect360. Port 5000 inside the container does not conflict with HeyTeam.

8 Reload Caddy Contabo

docker exec caddy caddy validate --config /etc/caddy/Caddyfile
docker exec caddy caddy reload --config /etc/caddy/Caddyfile

If validate fails, check the Destination path from step 6 and use that instead of /etc/caddy/Caddyfile.

Later Restore DB + copy storage

Do this after the empty app boots cleanly. Prefer a dry run before DNS cutover.

10 Dump old DB + restore PC → Contabo

# On machine that can reach current production DB
pg_dump -Fc -h OLD_HOST -U OLD_USER -d OLD_DB -f inspect360.dump
scp inspect360.dump root@169.58.40.94:/tmp/
# On Contabo
docker compose -f /opt/inspect360/docker-compose.contabo.yml stop inspect360
docker cp /tmp/inspect360.dump postgres:/tmp/inspect360.dump
docker exec -it postgres pg_restore --clean --if-exists --no-owner --no-acl \
  -U creativecloud -d inspect360 /tmp/inspect360.dump
docker compose -f /opt/inspect360/docker-compose.contabo.yml start inspect360

Adjust -U creativecloud if your admin user differs. Do not run db:push after a full restore.

11 Copy uploads PC → Contabo

scp storage-backup.tgz root@169.58.40.94:/tmp/
# On Contabo
docker compose -f /opt/inspect360/docker-compose.contabo.yml stop inspect360
VOL=$(docker volume inspect inspect360_storage -f '{{.Mountpoint}}')
